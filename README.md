# 铝厂余料转炉 · 再生料申报审核页

质检员在签发“最低再生料重量申报”前，用本系统核对称重账能否同时支撑各出货批的
再生料申报；档案员在审核页恢复炉次账里暂用估值的回炉转料重量（查档实称 +
守恒推算）。Flask + SQLite + 网络流/图求解，全部重量按**整数公斤**处理。

## 一、业务规则与建模

1. 账套按炉记录外购**原生料**、外购**再生料**，按出货批记录实称重量，
   并记录余料从哪一炉转往哪一炉、转出多少（实称重量）。
2. 每炉**总进料 = 总出料**（CSV 导入时强制校验，不平衡直接拒收）。
3. 每个出货批最多一张**有效签单**（部分唯一索引保证；撤销记录留历史）。
4. 重核时已签重量照旧；归到各出货批和回炉余料的再生料重量可重新调整。
5. 每炉**再生料进出相等**；每笔出货、每笔转料的再生料重量均以实称重量为上限。
6. 页面给出一套满足全部有效签单的出货/回炉再生料重量；新签或换账无解时
   说明具体瓶颈原因；提交失败则回滚，原账、签单与既有核定结果全部保留。

### 求解模型

带下界的整数网络流（`app/solver.py`，纯标准库实现的 Dinic）：

- `S → 炉`：容量为该炉外购再生料；
- `炉 → 出货批`：容量为批实称重量，**下界为有效签单下限**；
- `出货批 → T`：容量同为批实称重量；
- `炉 → 炉`：余料转料，容量为转料实称重量；
- 加 `T → S` 无穷边与超级源/汇，把带下界可行流转为最大流判定；
  可行后再跑一次 `S → T` 最大流，使出货承载尽量大。
- 容量均为整数，Dinic 保证得到整数解；无解时用残量网络最小割定位
  饱和的出货/转料通道与缺料炉，生成中文原因。

## 二、回炉转料暂用估值恢复（查档）

炉次账中部分转料重量是**暂用估值**。档案员在审核页按账套恢复它们
（`app/recovery.py`，纯标准库）：

1. **勾选**：逐笔勾选待恢复转料（同一对炉之间逐笔核算，勾选项原估值视为缺失），
   为每笔填调阅原磅单的**正整数分钟数**，或标为**无法调阅**。
2. **最少耗时清单**：把炉看作节点、勾选笔看作边。未知边能被每炉进出守恒
   方程唯一推出的充要条件是未知边**无环（森林）**。系统以求解
   “最大权森林的补集”（无法调阅边权 +∞）给出**总耗时最少**的一组待调磅单。
   若无法调阅的转料自身成环，则全部找回也推不全，页面指出
   **互相牵制的一组转料**（环上的每笔记录）。
3. **一次录齐**：档案员一次录齐清单上各磅单的实称公斤数；系统用未勾选重量
   与每炉守恒方程（森林叶剥离）唯一推出其余重量。全部恢复值为**非负整数**
   且**各炉平衡**时，才另存逐笔重量并标明**实查/推算**（不改账套原估值）。
4. **续办与容错**：清单按账套落库，换账后回到原账套可续办；
   录入或保存失败一律回滚，已有清单与既有恢复结果全部保留。

## 三、CSV 格式

UTF-8、首行表头，列固定为：

| 列 | 说明 |
|---|---|
| `record_type` | `furnace` / `batch` / `transfer` |
| `furnace` | 炉号（transfer 时为源炉） |
| `ref` | batch=出货批号；transfer=目标炉；furnace 留空 |
| `primary_kg` | 仅 furnace：外购原生料（留空按 0） |
| `recycled_kg` | 仅 furnace：外购再生料（留空按 0） |
| `weight_kg` | batch/transfer 的实称重量 |

示例见 `data/sample_ledger.csv`；`data/sample_recovery.csv` 含平行转料与
转料环，适合演示查档恢复。

## 四、运行

### Docker Compose（交付方式）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据库存放在命名卷 `audit-data`（容器内 `/data/audit.db`），
容器重建数据不丢；生产环境请修改 `AUDIT_SECRET_KEY`。

### 本地直接运行

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python wsgi.py            # 开发服务器，:8000
# 或
gunicorn --bind 0.0.0.0:8000 wsgi:app
```

## 五、页面操作

1. **上传 CSV**：首次直接导入；换账须勾选“替换当前账套”。导入即核定。
2. **核定结论**：展示可行方案或无解瓶颈；可随时“重新核定”。
3. **炉次账**：展示各炉进料/出料与平衡结果。
4. **出货批**：每行可签发（填正整数、不超过实称）或撤销签单，
   并显示该批核定再生料重量。
5. **余料转炉**：每笔转料的实称上限与核定再生料重量。
6. **暂用估值恢复（查档）**：勾选待恢复转料并填调阅分钟数/标无法调阅，
   生成最少耗时调档清单；一次录齐实称后另存逐笔恢复重量（实查/推算）；
   无法推全时页面列出互相牵制的转料环。
7. **签单台账**：有效/已撤销全部留痕。
8. **操作日志**：成功与失败（回滚）事件均记录。

  db.py         SQLite 建表、事务、签单/核定/恢复清单持久化
